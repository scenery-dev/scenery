# macOS .pkg Installer (MDM) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `.pkg` that installs the Scenery runner system-wide on macOS. A single root-owned LaunchAgent runs the daemon for every GUI user, the daemon wires that user's AI clients itself, and IT can upgrade or remove the runner from MDM.

**Architecture:** The runner gains a "pkg-managed" mode, detected from the binary's location. In that mode the daemon stands down per-user agents, enforces the Scenery client entry, and points client entries at the pkg binary. Brew/curl installs gain first-time-only client wiring. Packaging is shell scripts under `packaging/macos/`, a local `scripts/build-pkg.sh`, and a `pkg` job in `release.yml` whose signing steps run only when the Apple secrets exist.

**Tech Stack:** Rust workspace (`scenery-core`, `scenery-mcp`, `scenery-daemon`, `scenery-cli`), `pkgbuild`/`productbuild`/`lipo`, launchd, GitHub Actions (macOS runner).

**Spec:** `docs/superpowers/specs/2026-11-20-macos-pkg-design.md`

## Global Constraints

- Install root: `/Library/Application Support/Scenery/`. Binary: `/Library/Application Support/Scenery/bin/scenery` (root:wheel 0755).
- System LaunchAgent: `/Library/LaunchAgents/dev.scenery.agent.plist`, label `dev.scenery.agent` (root:wheel 0644). The per-user label `com.scenery.agent` and brew's `homebrew.mxcl.scenery` are unchanged.
- Package identifier: `dev.scenery.runner`. Managed-preferences domain: `dev.scenery.runner`, key `RegistryURL`.
- Symlinks: `/usr/local/bin/scenery` and `/usr/local/bin/scn`. Create them only if absent or already pointing at our binary.
- Uninstall script: `/Library/Application Support/Scenery/uninstall.sh`.
- Registry URL precedence: `SCENERY_REGISTRY_URL` env > managed pref `RegistryURL` > installer-choice file `/Library/Application Support/Scenery/registry-url` (dev pkg flavor only) > `DEFAULT_REGISTRY_URL`.
- Dev pkg flavor (`scenery-<v>-macos-dev.pkg`) shows a Prod/Dev choice on the Installer's Customize screen. Dev writes `https://dev.scenery.dev` to the choice file, and Prod writes nothing. The prod pkg shows no choice. Only the prod pkg is published in releases.
- Registry default stays `scenery_core::DEFAULT_REGISTRY_URL` (`https://app.scenery.dev`). An explicit `SCENERY_REGISTRY_URL` env always wins over managed prefs.
- No new crate dependencies (binary size + cargo-deny). Read managed prefs with `/usr/bin/defaults`.
- No pairing, tokens or codes in the pkg or its scripts.
- Signing/notarization only when secrets `APPLE_DEVELOPER_ID_APP_P12`, `APPLE_DEVELOPER_ID_INSTALLER_P12`, `APPLE_P12_PASSWORD`, `APPLE_NOTARY_KEY_P8`, `APPLE_NOTARY_KEY_ID`, `APPLE_NOTARY_ISSUER_ID` are all set. Otherwise build unsigned and log `pkg: unsigned (no Apple secrets)`.
- Never commit on weekdays 9am-5pm ET. `cargo clippy` + `cargo fmt` before every commit.

## Review Focus

1. **The user deletes the Scenery entry, then the daemon restarts.** In brew/curl mode the entry stays gone. In pkg mode it comes back. Tests: Task 3 `brew_mode_respects_user_removal`, `pkg_mode_restores_removed_entry`.
2. **A machine already on brew when the pkg lands.** Exactly one daemon holds the lock, and client entries point at the pkg binary, not `/opt/homebrew/bin/scenery`. Tests: Task 2 `stand_down_targets_both_user_labels`; Task 3 `pkg_mode_rewrites_foreign_binary_command`.
3. **Upgrade while a user is logged in.** The running process is the new binary within seconds, without waiting for the next login (the spaceghost stale-binary bug). Check: Task 6 acceptance step "upgrade swaps running binary".
4. **Claude Code installed after the runner.** Within one poll interval the entry appears, without a restart. Test: Task 3 `wire_pass_picks_up_newly_installed_client`.
5. **`uninstall.sh` on a reinstall/handover.** No server call is made and the device stays paired. Test: Task 4 `local_only_makes_no_server_calls`.

- Produces:

  - `pub enum WirePolicy { Enforce, FirstTimeOnly }`

  - `pub fn decide_wire(policy: WirePolicy, entry_present: bool, was_wired: bool) -> WireAction` where `WireAction { Write, MarkOnly, Skip }` (pure). The table:
